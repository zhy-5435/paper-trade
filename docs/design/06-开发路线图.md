# 06 开发路线图

> 分轮次开发，每轮是最终架构的子集而非另一套设计。包结构、表名、字段、状态机语义第一轮一次定准，后续轮次只加中间件与路由，不改上层逻辑。

## 第一轮：单库基础业务（无分布式中间件）
**目标**：不依赖任何分布式组件，跑通单体版核心业务。

开发顺序：
1. 用户与鉴权：注册、登录、JWT 校验（角色字段落库，管理员拦截后置）
2. 股票基础：股票信息 CRUD、模拟行情定时更新
3. 资金账户：开户、入金/出金（requestId 幂等）、余额查询、冻结/解冻（乐观锁 + 流水）
4. 持仓：持仓查询、增减、成本计算（含 T+1 冻结）
5. 订单：创建（规则校验 + 幂等）、状态机、查询
6. 简化撮合：JVM 内存盘口，下单事务提交后同步触发，直调订单/账户/持仓，含手续费与成交价口径
7. 最小日切（手动接口）：过期撤单解冻 → 行情日切 → T+1 清零（settlement 包第一轮唯一实现类，第四轮原地扩展完整清算）

**阶段简化（后续回填，不改最终设计）**：
- 撮合：始终内存盘口（不迁 Redis），正式版按股票分片 + 主备
- 成交回报：同步直调 → 正式版 RocketMQ 异步 + 幂等
- 数据访问：单库直连 → 正式版 ShardingSphere 分片 + 半同步读写分离
- 日切清算：手动最小日切（过期撤单解冻/行情日切/T+1 清零）→ 正式版完整七步清算 + 三方对账

**本轮不做**：清算批次/资产快照/三方对账、完整 RBAC 与操作审计（管理端仅简单 role 拦截）、用户主动撤单、分库分表、Redis、RocketMQ、全部选做项。

**验收**：单库跑通入金、限价买入、限价卖出三条链路（含 T+1、手续费、资金/持仓流水）。对手盘由两个测试用户互挂提供（不引入做市商）；T+1 次日可卖经手动日切接口验证。

## 第二轮：中间件接入
Redis 行情缓存与分布式锁、RocketMQ 成交回报异步化与幂等、用户主动撤单；启用 order_status_log、sys_operation_log（操作审计）。管理端维持 role=2 拦截，完整 RBAC 不纳入四轮计划。

## 第三轮：分片与高可用
ShardingSphere 分库分表与读写分离；docker-compose 多容器半同步主从复制（每片一主一从）；账户/持仓与订单同库分片落地。

## 第四轮：清算对账与指标验证
日终批量清算、行情日切、三方对账、异常标记，补齐第四条验收链路；JMeter 压测验证 TPS≥100（下单）/≥500（行情查询）；按需启用 tick 分表与 risk_rule。
