# 01 需求与边界

## 一、项目定位
模拟 A 股交易规则的分布式后端演示系统，全链路虚拟资金 + 模拟行情，无真实交易/支付对接；核心展示分布式架构设计、金融级数据一致性保障、海量数据存储优化能力，服务于校招面试。

## 二、角色边界
1. **C端交易用户**：注册登录、交易操作、资产查询
2. **运营管理员**：股票基础信息维护、行情管理、数据查看、对账差错处理

## 三、A股交易规则口径（全系统统一，各模块以此为准）
| 规则 | 口径 |
|------|------|
| 交易时段 | 交易日 9:30–11:30、13:00–15:00；演示环境可配置放宽以便测试 |
| 交易日历 | 简化为周一~周五；节假日日历表为扩展预留 |
| T+1 | 当日买入的股票当日不可卖出，日终清算后转为可卖 |
| 交易单位 | 买入按整手（默认 100 股/手）；卖出允许零股一次性委托 |
| 涨跌停 | 涨跌停价 = 昨收 × (1±幅度)，四舍五入到分；幅度按股票配置（主板 0.10 / 创业科创 0.20 / ST 0.05） |
| 成交价 | 连续竞价简化口径：以**对手方（盘口先挂单方）委托价**成交 |
| 撮合原则 | 价格优先、时间优先；买单最高价 ≥ 卖单最低价即成交 |
| 手续费 | 佣金双向 0.025%、最低 5 元；印花税卖出 0.05%；过户费忽略（简化口径，费率可配置）。卖出费用合计超过成交金额时按成交金额封顶（零股小额卖出避免负余额，演示简化口径） |
| 订单有效期 | 当日有效；日终未成交部分系统自动撤单并解冻 |

## 四、业务边界
### 必做（核心闭环）
1. **用户与账户中心**：注册登录、JWT 鉴权、个人信息管理；模拟入金/出金、余额查询、资金冻结/解冻；持仓查询、持仓成本与盈亏计算
2. **交易订单中心**：限价买卖单创建、订单列表查询、订单状态机（待撮合→部分成交→全部成交/已撤单/已过期）；交易规则校验（第三节全部适用项）；日终未成交单系统自动撤单
3. **简化撮合引擎**：买卖盘队列维护、价格时间优先撮合、生成成交记录、成交回报异步通知订单/资金/持仓
4. **清算与对账中心**：日终批量清算（自动撤单、行情日切、盈亏计算、资产快照）、资金/持仓/订单三方对账、异常标记与人工兜底
5. **基础行情中心**：股票基础信息维护、定时模拟生成行情（随机波动、涨跌停约束）、行情查询

### 选做（后续扩展）
用户主动撤单（第二轮）、市价单委托、基础风控（单笔/单日限额）、行情分时数据、运营后台统计、节假日交易日历。

## 五、核心验收链路
1. **入金**：注册→自动开户→模拟入金→余额更新
2. **限价买入**：查行情→提交买单（规则校验+冻结资金）→撮合成交→扣款并解冻差额→持仓增加（T+1 冻结）
3. **限价卖出**：提交卖单（校验可卖持仓+冻结持仓）→撮合成交→减仓结转成本→资金到账（扣费）
4. **日终清算**：收盘触发→未成交单撤单解冻→行情日切→盈亏与快照→三方对账→异常标记

> 演示口径：买卖对手盘由两个测试用户互挂提供（不引入做市商）；第一轮 T+1 次日可卖经手动日切接口验证，完整日终清算第四轮落地。

## 六、非功能指标
1. **一致性**：订单与资金最终一致，允许秒级延迟，日终对账兜底
2. **性能**：下单接口 TPS≥100，行情查询 TPS≥500
3. **数据规模**：订单/流水按百万级设计，支撑分库分表合理性

## 七、技术边界
1. 单体架构 + 分布式中间件，不做微服务拆分
2. 撮合引擎单机简化版（内存盘口 + 单线程串行，DB 持久化），不追求极致撮合性能
3. 本地 Docker 部署；主从用多容器真实复制模拟，不要求多机物理部署
