## 二、目标、范围与验收基线

### 2.1 目标（06 原文口径）
不依赖任何分布式组件，跑通单体版核心业务：单 MySQL + JVM 内存撮合 + 全同步调用，包结构/表结构/状态机一次定准，后续轮次只加中间件与路由。

### 2.2 本轮交付范围（按 06 开发顺序）

| # | 内容 | 模块 | 里程碑 |
|---|------|------|--------|
| 0 | 公共底座 + 种子持仓修补 | common | M0 |
| 1 | 注册、登录、JWT 校验、role 拦截、个人信息 | auth / user | M1 |
| 2 | 股票信息 CRUD、模拟行情定时更新、行情查询 | stock | M2 |
| 3 | 开户、入金/出金（requestId 幂等）、余额查询、冻结/解冻（乐观锁+流水） | account | M3 |
| 4 | 持仓查询、增减、成本计算（含 T+1 冻结） | position | M4 |
| 5 | 订单创建（规则校验+幂等）、状态机、查询 | order | M5 |
| 6 | JVM 内存盘口撮合，下单事务提交后同步触发，直调订单/账户/持仓，含手续费与成交价口径 | match | M6 |
| 7 | 最小日切手动接口：过期撤单解冻 → 行情日切 → T+1 清零 | settlement | M7 |

### 2.3 本轮明确不做（06 口径，防止范围蔓延）
清算批次/资产快照/三方对账（第四轮）、完整 RBAC（不纳入四轮计划）与操作审计（第二轮启用 sys_operation_log）、用户主动撤单（第二轮）、分库分表（第三轮）、Redis / RocketMQ（第二/三轮）、全部选做项（市价单、风控、分时、节假日日历等）。

### 2.4 验收基线（01§五 + 06）
单库跑通 **入金、限价买入、限价卖出** 三条链路（含 T+1、手续费、资金/持仓双侧流水）：
- 对手盘由 user01 / user02 互挂提供，不引入做市商；
- T+1「当日不可卖 → 手动日切 → 次日可卖」经 `POST /api/admin/settlement/run` 验证；
- 完整日终清算（第四条链路）不在本轮验收范围。

### 2.5 演进红线（02§八，本轮代码必须满足）
1. 四层单向依赖不破坏：接入层 → 业务层 →（中间件层，本轮空）→ 存储层；业务层不出现中间件 API。
2. 分片键提前落位：user_id / deal_time 已在表中，代码按单号查询/更新时**携带 user_id**（为第三轮路由预留习惯）。
3. 状态机与表结构以本轮为基线冻结，后续只加中间件与路由。
4. 面向接口一次到位：`OrderBook`（盘口）、`DealNotify`(成交回报) 本轮即定义接口，实现可替换（见 §3.3）。

## 三、工程基线

### 3.1 模块内布局约定
```
com.stocksim.<module>
├── controller      // 仅参数校验 + 调 service + 组装 Result，不写业务
├── service         // 接口 + impl；事务边界在 impl
├── mapper          // MP BaseMapper，复杂 SQL 走 XML（resources/mapper/<module>/）
├── entity          // 与表一一对应；强一致表 @Version
└── dto             // 请求/响应对象，金额字段 String 传输（05§一）
```
依赖方向遵守 04§一：auth→account；order→stock/account/position；match→order/stock（经 DealNotify 直调 account/position）；settlement→order/account/position/stock/match。**禁止反向与循环依赖**（position 不得调 order，account 不依赖任何业务模块）。

### 3.2 common 底座交付清单（M0）

| 组件 | 要点 |
|------|------|
| `Result` / `PageResult` | code=0 成功；分页 {records,total,page,size}（05§一） |
| `ErrorCode` | 按 05§二全量枚举：1xxx 通用 / 2xxx 账户 / 3xxx 订单 / 4xxx 撮合 / 5xxx 系统 |
| `BizException` + `GlobalExceptionHandler` | BizException→对应码；参数校验失败→1001；未登录→1002；无权限→1003；兜底→5001 并打日志 |
| `BizNoGenerator` | 「前缀+雪花ID」：order_no=O+id、deal_no=D+id、account_no=A+id、flow_no=F+id（≤20 字符）；派生流水号见 §6.5（≤22 字符，满足 VARCHAR(32)） |
| `MybatisPlusConfig` | 注册 `PaginationInnerInterceptor(MYSQL)` + `OptimisticLockerInnerInterceptor`（**不注册则 @Version 失效**）；显式 workerId 的 `DefaultIdentifierGenerator` Bean（读 stocksim.snowflake 配置） |
| `JacksonConfig` | BigDecimal 全局序列化为 String（05 金额字符串传输）；LocalDateTime 统一 `yyyy-MM-dd HH:mm:ss.SSS`（Boot 默认 ISO 格式，需显式注册） |
| `TraceIdFilter` | 每请求 UUID 入 MDC，日志 pattern 带 traceId（02§九） |
| `UserContext` | ThreadLocal 存 userId/role，拦截器 afterCompletion 必清理 |
| `TradeProperties` / `QuoteProperties` | @ConfigurationProperties 绑定 stocksim.trade / stocksim.quote（费率、session-check-enabled、刷新间隔、游走步长） |
| `TradeCalendar` | 简化周一~周五：isTradingDay / nextTradingDay（周五→下周一） |

### 3.3 演进接口（02§三「面向接口、一次到位」）

| 接口 | 第一轮实现 | 正式版替换 |
|------|-----------|-----------|
| `OrderBook` | 内存 TreeMap 价格排序 + 同价 FIFO，单实例 | 仍内存实现，按股票分片多实例 + 主备 |
| `DealNotify` | 同步直调：单事务完成买卖双方记账 | RocketMQ 生产者：买/卖两条记账消息 |

账户并发本轮仅 DB 乐观锁，**不预写锁切面**（第二轮叠加 Redisson）；行情读取收敛在 stock service 内，第二轮在其下加缓存实现。除上述两接口外不新增抽象，避免过度设计。

### 3.4 数据访问纪律
- 主键 MP `assign_id`（雪花），workerId 显式配置（已备 stocksim.snowflake.worker-id=1）。
- 流水表（fund_flow / position_flow / deal_record / deal_order_daily 的流水语义）**只追加**：实体无 deleted/update_time（deal_order_daily 除外，它是 upsert 汇总），服务层禁止调用 update/delete。
- 逻辑删除仅对含 deleted 字段的表生效（MP 全局配置已就位）；唯一键不含 deleted，注销释放 username 走追加后缀（本轮不实现注销，仅留口径）。
- 金额一律 `BigDecimal`，`setScale(2, HALF_UP)`；禁止 double 参与金额运算。

## 四、业务口径速查

### 4.1 文档已定口径（开发对照表）

| 口径 | 内容 | 来源 |
|------|------|------|
| 交易时段 | 9:30–11:30 / 13:00–15:00，`session-check-enabled=false` 时放宽（当前配置即放宽） | 01§三 |
| 交易日历 | 周一~周五 | 01§三 |
| T+1 | 当日买入当日不可卖；可卖 = total − frozen − today_buy；日切清零 today_buy | 01§三、04§8 |
| 交易单位 | 买入整手（lot_size=100）；卖出允许零股一次性委托 | 01§三 |
| 涨跌停 | 昨收×(1±幅度) 四舍五入到分；主板 0.10 / 创业科创 0.20 / ST 0.05；下单直读 stock_quote 冗余价（NOT NULL） | 01§三、03§四.3 |
| 成交价 | **对手方（先挂单方）委托价** | 01§三、04§7 |
| 撮合原则 | 价格优先、时间优先；买最高 ≥ 卖最低即成交；同股票串行 | 01§三、04§7 |
| 手续费 | 佣金双向 0.025% 最低 5 元；印花税卖出 0.05%；过户费忽略；卖出费用合计超成交金额按成交金额封顶；费率可配 | 01§三 |
| 订单有效期 | 当日有效；expire_time=当日收盘；日终未成交自动撤单解冻 | 01§三、04§6 |
| 买单冻结 | 委托价×数量 + 预估佣金（按委托价计）；卖单冻结持仓 | 04§6 |
| 可用资金 | balance − frozen_amount，不物理冗余 | 03§四.4 |
| 状态机 | 1待撮合→2部分成交→3全部成交 / 4已撤单 / 5部分成交后撤单 / 6已过期；version CAS 流转 | 03§四.8、04§6 |
| 幂等 | 下单/入金/出金必传 requestId（≤64）；(user_id,request_id) 去重；下单重复返回原单、入金/出金重复返回原流水结果 | 05§一、04§4 |
| 成交记账 | 每笔成交：deal_record + 买卖双方各两条 fund_flow（主流程 5/6 + 手续费 7）+ 各一条 position_flow（1/2）+ deal_order_daily 同事务累加 | 02§五、03§九.3 |
| 注册开户 | 注册提交 → 幂等开户（uk_user_id 兜底）→ 失败不阻断，首次入金/登录补偿 | 03§六.5 |
| 最小日切 | 手动接口三步：过期撤单解冻 → 行情日切 → today_buy 清零；不写批次/快照/对账 | 04§9、06 |
| 管理端鉴权 | /api/admin/** 按 JWT role=2 简单拦截，不做 RBAC | 04§2、05§一 |

### 4.2 实现级建议口径（文档未写死，本规划默认值）

| # | 口径 | 建议与理由 |
|---|------|-----------|
| P1 | 订单 trade_date 来源 | 取该股票 `stock_quote.trade_date`（行情是交易日权威）；expire_time = trade_date 15:00。**行情模拟不推进 trade_date，日切是唯一推进入口**，避免日期漂移 |
| P2 | 买单部分成交解冻 | 按成交数量占比解冻冻结额（HALF_UP 到分）；全部成交/撤单时解冻「剩余 frozen_amount 精确值」，保证冻结零残留 |
| P3 | 自成交防护 | 同一用户的买卖单不互相撮合（跳过），对齐主流风控；双测试用户验收不受影响 |
| P4 | 行情量额来源 | 随机游走只更新价格；total_volume/total_amount 由**实际成交**累加（与 deal_record 可勾稽）；change_ratio=(latest−pre_close)/pre_close |
| P5 | 无对手盘 | 不拒绝下单，订单挂盘待撮合（错误码 4001 预留不用）；无对手盘是常态而非异常 |
| P6 | 日切接口语义 | 每次调用 = 收盘当前交易日并推进到下一交易日（连调两次=推进两天，演示合法操作）；幂等靠「按股 WHERE trade_date=收盘日」+ 订单状态 CAS + 清零天然幂等，中断可重跑；不写 settlement_batch |
| P7 | 并发控制 | 乐观锁 CAS 冲突重试 ≤3 次，仍失败返回 4002/5001；撮合串行 = 每股 ReentrantLock（单实例足够，正式版换 Redisson） |
| P8 | 撮合触发与盘口更新 | 下单事务 **afterCommit** 触发（TransactionSynchronization）；盘口数量只在记账事务提交成功后更新；记账失败不推进 deal_seq、订单留在盘口等待下次触发 |
| P9 | 停牌股撮合 | 停牌期间不撮合（挂单保留），复牌后下次触发恢复；日切统一过期撤单 |
| P10 | 日切与撮合互斥 | 日切撤单同样获取该股票串行锁，再状态 CAS，杜绝与撮合并发冲突 |

### M0 公共底座 + 种子修补（1d）
- 交付：§3.2 全部组件；**修补 seed.sql：为 user02 注入初始持仓**（R1，方案见 §8）。
- 要点：雪花 workerId 显式 Bean；MP 双拦截器；Jackson 金额/时间格式；TraceIdFilter。
- DoD：`mvn spring-boot:run` 启动无错；`http://localhost:8080/doc.html` 可访问；actuator health UP；执行修补后种子，user02 持仓 1000 股且持仓流水勾稽成立。

### M1 auth / user（1d）
- 交付：POST register / login；GET/PUT profile；JwtAuthInterceptor（白名单：register/login/doc.html/webjars/**/v3/api-docs/**/swagger-resources/**/favicon.ico/actuator/**）；AdminRoleInterceptor（/api/admin/** 校验 role=2，否则 1003）。
- 要点：BCrypt 存储；JWT 含 userId/username/role + 24h 过期（配置已备）；注册两段式开户（P9/03§六.5）；profile 手机号脱敏；登录更新 last_login_time；禁用/注销状态拒绝登录。
- DoD：admin/user01/user02 登录成功（种子哈希已验证）；新注册用户自动开户余额 0；重复用户名报错；普通用户访问 /api/admin/** 返回 1003；无 token 返回 1002。

### M2 stock（1d）
- 交付：管理端股票新增/修改/停牌复牌退市；4 个行情查询端点；`@Scheduled(fixedDelayString)` 模拟行情 + 手动刷新端点。
- 要点：**新增股票同事务初始化 stock_quote**（pre_close=发行价、涨跌停必算、trade_date=当前交易日）；随机游走 latest×(1±step×random) 钳制在涨跌停内、四舍五入到分；首笔行情填 open，维护 high/low；version CAS 防定时/手动刷新并发；量额按 P4 由成交累加；session-check-enabled 控制是否仅交易时段生成。
- DoD：行情每 3s 跳动且始终在涨跌停内；管理端新建股票后行情立即可查；停牌状态变更生效。

### M3 account（1.5d）
- 交付：GET account（余额/冻结/可用/总资产）；deposit/withdraw（requestId 幂等）；GET flows 分页；内部服务 freeze/unfreeze/deduct/credit（供 order/match/settlement 调用）。
- 要点：每笔变动同事务「CAS 更新 user_account + 追加 fund_flow（含前后余额/冻结）」；入金/出金幂等查 uk_user_request 返回原流水结果；出金校验可用资金；CHECK 约束兜底（违反即记账 bug，抛 5001 并告警日志）；流水号发号器生成，记账流水 request_id=NULL。
- DoD：链路①注册→开户→入金→余额可查；重复 requestId 余额不变；超额出金 2001；§7.4 资金对账 SQL 零差异。

### M4 position（1d）
- 交付：GET positions（实时市值/浮盈/可用数量）、GET flows 分页；内部服务 增仓/减仓/冻结/解冻/成本结转。
- 要点：买入成本加权平均（含买入费用）：cost += 成交金额+费用，avg = cost/total（4 位小数）；卖出按均价结转，**清仓时 cost_amount 归零防残留**；买入 today_buy_qty += qty；卖出成交减仓同时解冻 frozen_qty；每次变动追加 position_flow（含冻结 4/解冻 5，前后量齐全）；市值/浮盈查询时实时算不落库。
- DoD：单元测试覆盖加权成本、卖出结转、清仓归零、可卖数量（T+1）、冻结/解冻流水勾稽。

### M5 order（2d）
- 交付：POST orders（限价买/卖）、GET orders（状态/时间筛选分页）、GET orders/{orderNo}（携带 userId 查询）。
- 要点：先查 (user_id,request_id) 幂等返回原单；校验链：交易时段→股票上市状态→涨跌停→整手/零股→T+1 可卖持仓→可用资金/持仓→账户状态；买单冻结=价×量+预估佣金，同事务写 fund_flow(3) + 订单；卖单冻结持仓写 position_flow(4)；流水号 `{order_no}F3`/`{order_no}P4`；状态机 CAS 工具方法（M6/M7 复用）；校验拒绝不落单直接错误码。
- DoD：无对手盘下单挂起（状态 1）、冻结额正确；重复 requestId 返回原单；3001/3002/3003/3004/3005/2001/2003 各拒绝分支逐一验证。

### M6 match（2.5d，本轮难度最高）
- 交付：`OrderBook` 接口 + 内存实现；`MatchEngine`（每股锁 + 撮合循环）；`DealNotify` 接口 + 同步实现；deal_record 落库 + deal_seq（AtomicLong，启动取 MAX）；启动重建盘口。
- 要点：
  - 撮合循环见 §6.6；成交价=先挂单方委托价；跳过自成交（P3）与停牌股（P9）。
  - 每笔成交一个本地事务：deal_record + 买方记账（订单 CAS、扣款 5、佣金 7、增仓 1、today_buy、deal_order_daily upsert）+ 卖方记账（订单 CAS、减仓结转 2、入账 6、佣金+印花税 7 封顶、deal_order_daily upsert）。第一轮单库买卖双方同事务，接口上仍按「一笔成交一次通知」组织，第二轮拆两条消息不改上层。
  - 流水号严格按 §6.5 派生；重放/重试被 uk_flow_no 拦截整体回滚。
  - afterCommit 触发（P8）；记账成功才更新盘口；失败留单待下次触发。
  - 启动重建：status IN (1,2) 且剩余数量>0 的订单按 create_time 入盘；deal_seq=MAX(deal_seq)（走 uk_deal_seq）。
- DoD：链路②③全通；§6.2–6.4 数值例逐一核对；重启后挂单仍可成交、deal_seq 不回退。

### M7 settlement 最小日切 + 集成验收（2d）
- 交付：`POST /api/admin/settlement/run`（settlement 包本轮唯一实现类，第四轮原地扩展七步，不搬家）；集成测试与验收执行。
- 要点：三步见 §6.8；撤单获取股票锁 + 状态 CAS（→6 已过期，reject_reason 注明），双侧解冻流水 `{order_no}C4`/`{order_no}C5`，同时从盘口移除；行情日切按股 WHERE trade_date=收盘日（pre_close=latest、重算涨跌停、open/high/low 置 NULL、量额清零、trade_date=nextTradingDay）；today_buy_qty 全量清零（不单独落流水，03§四.7 口径）。
- DoD：§7.3 验收用例 A1–A18 全过；§7.4 三条对账 SQL 零差异；验收记录归档（建议附验收截图/HTTP 记录，面试展示用）。

## 六、关键实现细节（含数值例，开发时逐条核对）

### 6.1 事务边界与调用时序
```
下单请求
 └─ 事务T1：规则校验 → 幂等查重 → 落 trade_order → 冻结（account/position CAS + 双侧流水）
     └─ T1 afterCommit → MatchEngine.onNewOrder(stock)
         └─ 获取股票锁 → 新单入盘 → 撮合循环
             └─ 每笔成交 → 事务T2：deal_record + 买卖双方订单/账户/持仓/流水/日汇总
                 └─ T2 提交成功 → 更新盘口数量、推进 deal_seq
```
严禁在 T1 内撮合（读不到未提交冻结、且拉长事务）；严禁盘口先扣减后记账（失败无法回滚内存）。

### 6.2 手续费数值例（费率取当前配置）
| 场景 | 成交金额 | 佣金 max(金额×0.00025, 5) | 印花税(卖) | 费用合计 | 备注 |
|------|---------|--------------------------|-----------|---------|------|
| 买 100 股 @10.00 | 1000.00 | 5.00 | — | 5.00 | 冻结=1000+5=1005.00（预估佣金按委托价） |
| 卖 100 股 @10.00 | 1000.00 | 5.00 | 0.50 | 5.50 | 入账 994.50 |
| 卖 1 股 @5.00（零股封顶） | 5.00 | 5.00 | 0.00（0.0025→分） | 5.00 | 费用=成交金额封顶，入账 0.00，余额不为负 |

### 6.3 买单冻结→部分成交→撤单全数值例
初始入金 100000.00；买 200 股 @10.00，冻结 2005.00（2000 + max(0.5,5)）：

| 步骤 | balance | frozen | 可用 | 持仓 | 说明 |
|------|---------|--------|------|------|------|
| 下单后 | 100000.00 | 2005.00 | 97995.00 | 0 | fund_flow 3，{order_no}F3 |
| 部分成交 100 股 @9.80 | 99015.00 | 1002.50 | 98012.50 | 100（today_buy=100，可卖 0） | 解冻 2005×100/200=1002.50（P2）；扣款 980（5）+佣金 5（7）；成本 985，均价 9.8500 |
| 日切撤剩余 100 股 | 99015.00 | 0.00 | 99015.00 | 100（today_buy 清零后可卖 100） | 解冻剩余精确值 1002.50，状态→5；{order_no}C4 |

核对：总支出 985.00 = 100 股 ×9.80 + 佣金 5.00 ✓；冻结零残留 ✓。

### 6.4 成交价口径例
user02 先挂卖 100 股 @9.90，user01 后挂买 100 股 @10.10 → **成交 @9.90**（先挂单方价）。
买方：扣 990 + 佣金 5 = 995；卖方：入 990 − (佣金 5 + 印花税 0.50) = 984.50。

### 6.5 流水号派生规则（03§六.3，长度均 ≤32）

| 场景 | fund_flow.flow_no | position_flow.flow_no |
|------|-------------------|------------------------|
| 入金/出金 | 发号器 F+雪花，幂等靠 uk_user_request | — |
| 下单冻结 | {order_no}F3 | {order_no}P4 |
| 买入成交 | {deal_no}B5（扣款+解冻）+ {deal_no}B7（佣金） | {deal_no}B1 |
| 卖出成交 | {deal_no}S6（入账）+ {deal_no}S7（佣金+印花税） | {deal_no}S2（减仓+同步解冻） |
| 撤单/过期解冻 | {order_no}C4 | {order_no}C5 |
| 清算/冲正（第四轮） | 发号器生成，biz_no=批次号查重 | 同左 |

### 6.6 撮合循环伪代码
```
lock(stock):
  book = orderBookOf(stock)          // 启动已重建；买单降序/卖单升序 TreeMap，同价 FIFO
  while book.bestBid != null && book.bestAsk != null
        && bestBid.price >= bestAsk.price
        && bestBid.userId != bestAsk.userId        // P3 自成交防护
        && stock.status == 上市:                    // P9
      resting = 先挂单方(create_time 早者)
      price   = resting.price                      // 成交价=对手方委托价
      qty     = min(bid.remainQty, ask.remainQty)
      deal    = buildDeal(price, qty)              // deal_seq 预分配
      try:
          dealNotify.onDeal(deal)                  // 事务T2：落库+双侧记账
          book.reduce(bid, qty); book.reduce(ask, qty)
          dealSeq.commit()
      catch:
          log.error(...); break                    // 盘口不动、seq 留空洞可接受，订单留盘
```

### 6.7 启动重建（DB 即顺序日志，盘口可丢）
1. `SELECT MAX(deal_seq)`（走 uk_deal_seq 索引）→ AtomicLong 初始化；
2. 查 trade_order status IN (1,2) 且 entrust_qty > matched_qty，按 stock_code、create_time 排序入盘（剩余数量=entrust−matched）；
3. 不重放记账（账务已在 DB），重建只恢复盘口。秒级 RTO，与 02§六口径一致。

### 6.8 最小日切三步（幂等可重跑，P6）
设收盘日 D = 当前行情统一 trade_date：
1. **过期撤单解冻**：按 idx_trade_date_status 扫 trade_date=D AND status IN (1,2)；逐单获取股票锁 → CAS 状态→6 → 买单解冻剩余 frozen_amount（C4）/卖单解冻剩余 frozen_qty（C5）→ 盘口移除；
2. **行情日切**：逐股 `UPDATE ... WHERE trade_date=D`：pre_close=latest、重算涨跌停（ROUND 到分）、open/high/low=NULL、量额=0、change_ratio=0、trade_date=nextTradingDay(D)、version CAS；
3. **T+1 清零**：`UPDATE user_position SET today_buy_qty=0 WHERE today_buy_qty>0`（不落流水，03 口径）。

重跑安全性：步骤 1 状态 CAS 天然幂等；步骤 2 WHERE trade_date=D 使已日切的股票不再命中；步骤 3 清零幂等。不写 settlement_batch（第四轮再引入批次与 settle_step）。

### 6.9 T+1 闭环例
user01 当日买入成交 100 股 → today_buy_qty=100，可卖=100−0−100=0 → 当日卖单拒绝 3003 → 管理员日切 → today_buy_qty=0 → 次日卖单通过校验并成交。

### 7.4 对账抽查 SQL（验收与日常自检，03§九.6 口径的本轮简化版）
```sql
-- 资金：流水累计 = 账户余额/冻结
SELECT a.user_id, a.balance, COALESCE(SUM(f.change_balance),0) AS flow_balance,
       a.frozen_amount, COALESCE(SUM(f.change_frozen),0) AS flow_frozen
FROM user_account a LEFT JOIN fund_flow f ON f.user_id = a.user_id
GROUP BY a.user_id, a.balance, a.frozen_amount
HAVING a.balance <> flow_balance OR a.frozen_amount <> flow_frozen;

-- 持仓：流水累计 = 持仓总量/冻结
SELECT p.user_id, p.stock_code, p.total_qty, COALESCE(SUM(f.change_qty),0) AS flow_qty,
       p.frozen_qty, COALESCE(SUM(f.change_frozen),0) AS flow_frozen
FROM user_position p LEFT JOIN position_flow f
  ON f.user_id = p.user_id AND f.stock_code = p.stock_code
GROUP BY p.user_id, p.stock_code, p.total_qty, p.frozen_qty
HAVING p.total_qty <> flow_qty OR p.frozen_qty <> flow_frozen;

-- 订单：订单累计 = 成交日汇总
SELECT o.order_no, o.matched_qty, COALESCE(SUM(d.deal_qty),0) AS daily_qty,
       o.matched_amount, COALESCE(SUM(d.deal_amount),0) AS daily_amount,
       o.fee_amount, COALESCE(SUM(d.fee_amount),0) AS daily_fee
FROM trade_order o LEFT JOIN deal_order_daily d
  ON d.user_id = o.user_id AND d.order_no = o.order_no
GROUP BY o.order_no, o.matched_qty, o.matched_amount, o.fee_amount
HAVING o.matched_qty <> daily_qty OR o.matched_amount <> daily_amount OR o.fee_amount <> daily_fee;
```
