## 三、M1 Redis 缓存 + 布隆过滤器（99e84bf）

### 步骤
1. RedisCacheClient 完善 + CacheKeys + 自定义 record codec。
2. QuoteService/StockService 读路径缓存（quote 3s±打散 / stock 30min）+ 布隆拒绝。
3. RBloomFilter 启动初始化 + 新股加入；刷新/管理端变更（延迟双删）/日切全量删行情缓存。
4. Redis 故障读降级回源 DB；新增 18 单测，合计 165 绿。

### 遇到的问题
- **final record 序列化（核心坑，§6.5/Q1）**：
  - Redisson `JsonJacksonCodec` 对 final record **不写 `@class`**，解码缺类型 id 失败。
  - `TypedJsonJacksonCodec` 重配 visibility 又**破坏 record creator 探测**，同样不可用。
  - 修复：改用 `BaseCodec` + 独立 `ObjectMapper`（JavaTimeModule/ParameterNamesModule、关闭 WRITE_DATES_AS_TIMESTAMPS），按**显式 Class** 解码。实测校正后回写规划 §6.5。
- **缓存雪崩**：固定 TTL 致大量 key 同时失效。修复：quote TTL 3s ± 随机打散（`quoteTtlWithJitter`）。
- **读写并发回填旧值**：管理端股票变更后立即删缓存，可能被并发读回填旧值。修复：**延迟 1s 二次删**。
- **R7 缓存与 DB 不一致窗口**：缓存仅加速，任何不一致以 MySQL + 对账兜底；读路径降级安全（get→null 回源、布隆→「不确定」放行）。

## 四、M2 Redisson 三锁（4cb8207）

### 步骤
1. MatchEngine/Settlement 股票锁替换为 LockProvider（`lockOf` 返回 Lock，撮合 tryLock 3s 超时留单）。
2. 账户锁包 createOrder/applyMoney 重试循环**外层**（先锁后事务，叠加 CAS）。
3. 日切入口选主锁 tryLock 0，占用即 5001。
4. 锁后端故障统一 fail-fast 5001；新增 5 锁单测，合计 170 绿。

### 遇到的问题
- **Q2 锁位置**：锁须在**外层事务入口**获取，先于事务提交释放无效（事务内加锁→提交前释放→并发窗口）。修复：账户锁包在重试循环外层，先锁后事务。
- **锁序死锁**：多锁场景须固定顺序。修复：全局锁序 **stock→account**。
- **R5 Redis 故障裸奔**：锁失效会并发超扣。修复：fail-fast——交易路径 5001、行情降级读 DB，**不静默跳过锁**。
- DoD 验证：并发入金/出金/下单无超扣、并发日切一执行一拒绝、停 Redis 写路径 5001 行情可读、对账零差异。

## 六、M4 RocketMQ 异步记账（c6a3b8e）

### 步骤
1. DealBookingService 抽取（单侧记账口径只有一份）+ SyncDealNotify 复用。
2. MQ 生产者 + 事务监听器 + MqDealNotify + notify 开关（Q4）。
3. 买/卖顺序消费者 + 幂等前置 + 重试上限 + test-mode（Q5）。
4. Q6 重建口径切换 deal_record 权威 + MatchEngineTest 适配。
5. 补偿任务 DealCompensateTask + DLQ 告警消费者（Q7）。
6. M4 单测 + MQ 集成测试 + 全绿；冒烟 B6–B10 + 死信告警 + 集成测试实跑 + 四条对账零差异。

### 遇到的问题
- **事务消息 header 前缀（关键缺陷）**：rocketmq-spring 2.3.1 适配器给 header 加前缀 `RocketMQHeaders.PREFIX="rocketmq_"`；DealTransactionListener 用裸常量读 TAGS/KEYS 返回 null，**事务执行器误走 SELL 分支全部 ROLLBACK**，成交事实无法落库。修复：读 `PREFIX+TAGS` / `PREFIX+KEYS`。此缺陷直接阻断异步链路，是 M4 最关键的坑。
- **R2 回查依赖内存状态**：重启后回查误判 ROLLBACK 丢通知。修复：回查**只查 deal_record by deal_no 存在性**（COMMIT/ROLLBACK），不依赖内存。
- **R6 顺序消费失败阻塞队列**：顺序消费默认无限重试。修复：显式 `maxReconsumeTimes=5`，耗尽→死信 + 告警 + 补偿。
- **R4 重建用 matched_qty**：在途成交二次撮合。修复：Q6 剩余数量 = `entrust_qty − Σdeal_record.deal_qty`（权威），剩余=0 不入盘。
- **F1/F2 语义切分**：F1 未落库（半消息失败/执行器 ROLLBACK）→ 抛 MATCH_CONFLICT 换新 dealNo 重试；F2 已落库发送不确定（UNKNOWN/end-ack 失败/SELL 发送失败）→ **不换 dealNo**、正常返回，回查 + 补偿兜底。
- **冒烟环境坑**：
  - jar 名误用 `stock-sim-1.0.0.jar`（不存在），实际为 `target/paper-trade-0.0.1-SNAPSHOT.jar`（pom artifactId=paper-trade）。
  - `nohup java &` 的 `$!` 是 wrapper pid 非真实 java pid；须 `netstat -ano | grep ':8080 ' | grep LISTENING` 取真实 pid。
  - jar 被运行中应用锁定，重启前须先 kill。
- **已知偶发**：`JwtServiceTest.tamperedTokenRejected` 约 6% 闪断（与本轮无关），重跑即绿，不修改。

## 七、M5 操作审计 + 接口限流（698f330）

### 步骤
1. pom 加 `spring-boot-starter-aop`。
2. 限流切面 RateLimitAspect（Q8）+ 端点接入（下单 ORDER、行情批量 QUOTE）。
3. 审计实体/Mapper/类型/注解/服务（Q9）+ AuditAspect + admin 端点 + 登录审计。
4. M5 单测（限流切面/审计服务）+ 全绿（231）；冒烟 B13/B14 + 审计故障注入。

### 遇到的问题
- **限流并发首次初始化竞态（核心 BUG）**：并行突发下报 `RateLimiter is not initialized`（RedisException→5001）。根因：旧实现用 `Set.add(key)` 在 `setRate` **完成前**就标记已初始化，竞态线程跳过 setRate 直接 tryAcquire 命中未初始化限流器。修复：`ConcurrentHashMap.computeIfAbsent(key, k->{setRate(k,rate); return TRUE;})` 原子初始化，同 key 线程阻塞至 setRate 完成；新增 8 线程并发回归测试（CountDownLatch 卡 setRate，验证全部 ok + setRate 仅一次）。
- **R16 速率持久化**：`trySetRate` 不更新已存在速率，改阈值重启不生效。修复：首次使用 `setRate` **覆盖写入**；本地 Map 记已初始化 key，阈值改重启生效。
- **Q9 审计切面时机**：`afterCompletion` 在失败时也触发（不可用）。修复：`@AfterReturning` **仅成功落库**；insert 在 controller 层独立 autocommit（业务事务外），失败仅 warn 不回滚业务。
- **登录审计 UserContext 缺失**：登录时 UserContext 尚未设置。修复：auth 内显式 `recordLogin(operatorId, operatorName, args)`。
- **密码脱敏**：detail 请求摘要 JSON 递归掩码 password 字段为 `***`。
- **单测编译坑**：
  - `insert(any())` 歧义（BaseMapper 有 `insert(T)` 与 `insert(Collection<T>)`）→ 改 `insert(any(OperationLog.class))`。
  - 并发测试 Callable lambda 调 `aspect.around()` 抛 Throwable，但 `Callable.call()` 仅抛 Exception → `catch(Throwable t){throw new RuntimeException(t);}`；测试方法签名 `throws Exception` → `throws Throwable`。
- **冒烟中文编码坑**：curl JSON body 含中文 stockName 返回 1001（bash 编码 artifact，非生产 BUG，真实 UTF-8 客户端正常）；冒烟改用 ASCII 名。
- **审计故障注入验证**：用可逆 `RENAME TABLE` 模拟落库失败，证明业务不受影响（仅 warn），验后还原。

### 遇到的问题
- **B6 盘口污染**：首次构造在途窗口时，新挂卖单被**遗留 resting 买单**（B3 再下单）抢先撮合，导致目标买单 matched=0/deal_record=0，撤单直接成功而非 4002。根因：未清空盘口遗留挂单。修复：先撤掉遗留挂单清盘，再以「买 200@10.10 + 卖 100@9.90」部成场景构造干净在途窗口（matched0/deal100→4002，resume 后 matched100 status2→撤单 status5）。
- **B13 限流端点误用**：单行情路径 `/api/stocks/{code}/quote` **无 @RateLimit**，限流注解在批量端点 `/api/quotes`。误 burst 单路径恒不限流。修复：改 burst 批量端点。
- **B13 并发构造不足**：bash 顺序 curl 与 fork 并行均因进程启动/TCP 连接 stagger 跨度 >1s，未超 20/s 阈值。修复：用 Node `Promise.all` 真正同时发 60 请求 → 20 放行 40 拒绝，精确验证阈值。
- **B11 缓存命中证明时机**：quote TTL 仅 3s±打散，查询与检查间隔过长致 key 已过期（exists=0）。修复：查询后**立即**查 Redis（exists=1 ttl=2s）证明命中路径。
- **验收顺序编排**：日切（A13/B15）会推进 trade_date 并过期挂单，须在异步可靠性用例（B8/B9/B10/B16 需活跃成交/挂单）**之后**执行；停 Redis（B11）影响锁，须在并发日切（B15 需 Redis 锁）前恢复。
- **控制台中文乱码**：Windows GBK 控制台显示 reject_reason 乱码，但 DB 存 UTF-8 正确；归档文档以 UTF-8 重写证据。

### 验收结论
B1–B16 全过；A 系列异步复验数值与第一轮一致；§7.4 四条对账 SQL 零差异；order_status_log 抽查零不一致；`mvn test` 231 绿（1 跳过 = MqAsyncBookingIntegrationTest 中间件门控，已由手动冒烟覆盖）。

## 十、面试复盘亮点（最具代表性的三个 BUG）

1. **M4 事务消息 header 前缀**：框架适配器隐式加前缀致裸常量读 null，事务执行器误走 SELL 分支全 ROLLBACK——表现为「异步链路完全不通」，根因却在 header 读取约定。教训：集成第三方框架须核对适配层的隐式约定（前缀/包装），不能只看原生 API 常量。
2. **M5 限流并发首次初始化竞态**：`Set.add` 先标记后初始化，竞态线程命中未初始化限流器报 5001。修复用 `computeIfAbsent` 原子化「初始化+标记」。教训：「检查-then-act」在并发下必须原子化，标记位不能在副作用完成前置位。
3. **M3/M4 在途记账与撤单互斥**：异步落库与记账解耦后，撤单须以 `Σdeal_record.deal_qty==matched_qty` 判定在途，否则双重解冻致 frozen 为负、CHECK 拒绝、死信。教训：异步化引入「事实已成立、账务未完成」中间态，所有写路径都要显式处理该窗口（撤单 4002、重建 deal_record 权威口径）。
