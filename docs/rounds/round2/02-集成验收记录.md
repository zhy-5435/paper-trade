## 六、§7.4 四条对账 SQL（均零行）

```sql
-- R1 资金：流水累计 = 账户余额/冻结
SELECT a.user_id, a.balance, COALESCE(SUM(f.change_balance),0) AS flow_balance,
       a.frozen_amount, COALESCE(SUM(f.change_frozen),0) AS flow_frozen
FROM user_account a LEFT JOIN fund_flow f ON f.user_id = a.user_id
GROUP BY a.user_id, a.balance, a.frozen_amount
HAVING a.balance <> flow_balance OR a.frozen_amount <> flow_frozen;

-- R1 持仓：流水累计 = 持仓总量/冻结
SELECT p.user_id, p.stock_code, p.total_qty, COALESCE(SUM(f.change_qty),0) AS flow_qty,
       p.frozen_qty, COALESCE(SUM(f.change_frozen),0) AS flow_frozen
FROM user_position p LEFT JOIN position_flow f
  ON f.user_id = p.user_id AND f.stock_code = p.stock_code
GROUP BY p.user_id, p.stock_code, p.total_qty, p.frozen_qty
HAVING p.total_qty <> flow_qty OR p.frozen_qty <> flow_frozen;

-- R1 订单：订单累计 = 成交日汇总
SELECT o.order_no, o.matched_qty, COALESCE(SUM(d.deal_qty),0) AS daily_qty,
       o.matched_amount, COALESCE(SUM(d.deal_amount),0) AS daily_amount,
       o.fee_amount, COALESCE(SUM(d.fee_amount),0) AS daily_fee
FROM trade_order o LEFT JOIN deal_order_daily d
  ON d.user_id = o.user_id AND d.order_no = o.order_no
GROUP BY o.order_no, o.matched_qty, o.matched_amount, o.fee_amount
HAVING o.matched_qty <> daily_qty OR o.matched_amount <> daily_amount OR o.fee_amount <> daily_fee;

-- R2 成交权威明细 vs 订单成交日汇总（单库版权威交叉核对，第三轮移离线）
SELECT o.order_no,
       COALESCE(SUM(r.deal_qty),0)  AS record_qty,
       COALESCE(MAX(d.deal_qty),0)  AS daily_qty
FROM trade_order o
LEFT JOIN deal_record r
  ON r.buyer_order_no = o.order_no OR r.seller_order_no = o.order_no
LEFT JOIN deal_order_daily d
  ON d.user_id = o.user_id AND d.order_no = o.order_no
GROUP BY o.order_no
HAVING record_qty <> daily_qty;
```

四条 HAVING 均无命中行。order_status_log 抽查（最新日志 to_status vs trade_order.status）亦 0 不一致。

## 十、本轮口径与简化（详见 docs/rounds/round2/01）

- 异步链路：下单 T1 不变；afterCommit 撮合，每笔成交发事务消息 BUY（本地事务 T2' 落 deal_record + 行情量额）→ COMMIT 后发 SELL；消费端 order_no 顺序消费、买/卖两组、maxReconsumeTimes=5 → 死信 + 告警 + 补偿。
- 不变量：deal_record 落库即成交事实；T2' 提交后严禁换新 dealNo 重试；盘口先落库后扣减；回查只查 deal_record（不依赖内存）；消费端不跨用户合并事务。
- 幂等矩阵：本侧 B5/S6 流水存在 → ACK（先于 requireOpenOrder，终态重放不误入死信）；漏网者 uk_flow_no 整体回滚；重启重建按 deal_record 权威口径（remain=entrust−Σdeal_qty）。
- 撤单核心：用户撤单与日切过期撤单共用；股票锁 → 在途检查（Σdeal_qty==matched_qty 否则 4002/跳过）→ 状态 CAS → 精确解冻（买 C4 / 卖 C5）→ 盘口移除 → 状态日志（type2/3）。
- 缓存：`quote:{code}`（TTL 3s±打散）、`stock:{code}`（30min）、`bloom:stock`；自定义 BaseCodec + 独立 ObjectMapper 按显式 Class 解码；失效时机 refreshOne 成功 / 股票变更延迟 1s 二次删 / 日切全量删行情缓存；读路径降级安全（get→null 回源、布隆→放行）。
- 限流：RateType.OVERALL 每用户 key=`rl:{type}:{userId}`，ORDER 5/s、QUOTE 20/s（可配），tryAcquire 0-wait 失败→1004；首次使用 computeIfAbsent 原子 setRate（R16 trySetRate 不更新已有速率），阈值改重启生效。
- 审计：@AfterReturning 仅成功落库（controller 层独立 autocommit，失败仅 warn 不回滚业务）；detail 请求摘要 JSON（密码掩码 `***`）；登录审计显式记录（登录时 UserContext 未设置）。
- 分布式锁：MatchEngine/Settlement 股票锁、日切选主锁、账户锁均接入 LockProvider（Redisson）；Redis 故障 fail-fast（交易 5001、行情降级读 DB），不静默跳过锁。
