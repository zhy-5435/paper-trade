## 二、目标、范围与验收基线

### 2.1 目标（06 原文口径）
Redis 行情缓存与分布式锁、RocketMQ 成交回报异步化与幂等、用户主动撤单；启用 order_status_log、sys_operation_log（操作审计）。**单实例 + 单 MySQL 部署形态不变，只加中间件与路由，不改上层业务逻辑**（02§八）。

### 2.2 本轮交付范围

| # | 内容 | 模块 | 里程碑 |
|---|------|------|--------|
| 0 | RocketMQ compose + 扩展表 + 依赖配置 + 连通冒烟 | docker / common | M0 |
| 1 | 行情短 TTL 缓存 + 股票信息长 TTL 缓存 + 布隆过滤器 + 失效与降级 | stock | M1 |
| 2 | Redisson 分布式锁：撮合/撤单股票锁、账户锁、清算选主锁 | common / match / account / settlement | M2 |
| 3 | 用户主动撤单 + order_status_log 全场景落日志 | order / settlement | M3 |
| 4 | RocketMQ 异步记账：事务消息 + 回查 + 顺序消费 + 幂等 + 死信 + 补偿 | mq / match | M4 |
| 5 | sys_operation_log 操作审计 + 接口限流基础版 | common / auth | M5 |
| 6 | 集成验收 + 可靠性用例 + 归档 | 全部 | M6 |

### 2.3 本轮明确不做（防止范围蔓延）
分库分表 / 读写分离（第三轮）；清算批次 / 资产快照 / 三方对账（第四轮）；完整 RBAC（不纳入四轮计划）；前端 SPA / WebSocket（guides/01 另行评估）；deal_seq Redis INCR（集群阶段，02§六）；市价单 / 风控 / 分时 / 节假日日历（选做）；tick / risk_rule 表不启用；JMeter 压测（第四轮）。

### 2.4 验收基线
1. **回归**：第一轮三条链路 + T+1 闭环在异步模式下复验通过；147 单测保持全绿（sync 实现）。
2. **撤单链路**：下单 → 部分成交 → 撤单 → 解冻零残留 → 资金/持仓可再用。
3. **异步记账链路**：下单 → 成交落库 → 买/卖两条消息 → 各自同库事务记账 → 三条对账 SQL 零差异。
4. **可靠性**：消息重放幂等、消费者重启不丢、事务回查正确、死信可发现可补偿。
5. **缓存与降级**：命中/回源/更新失效/布隆防穿透；Redis 故障时行情可读（回源 DB）、交易快速失败（5001）不裸奔。

### 2.5 演进红线（02§八，本轮代码必须满足）
1. 四层单向依赖不破坏：**RocketMQ API 只出现在 mq 包**；Redisson 收敛在 common 锁/限流/缓存组件，业务侧只见 `java.util.concurrent.locks.Lock` 与 service 接口。
2. `DealNotify` 双实现配置切换（Q11）：`stocksim.deal.notify=sync|mq`，默认 mq；测试用 sync 保确定性——这是 02§一「中间件可插拔」的落地，不是兼容包袱。
3. 13 张核心表结构冻结，本轮只启用 2 张扩展表；流水号派生规则（03§六.3）一字不改。
4. 按单号查询/更新继续携带 user_id（第三轮分片路由习惯）。

### 2.6 端点变化（05 口径）
新增 `POST /api/orders/{orderNo}/cancel`（共 24 个端点）；`POST /api/orders` 与行情查询叠加限流（超频 1004）。审计本轮只写不查（05 无审计查询端点，验收直查 DB）。

| 项 | 内容 |

| 扩展表 | 执行 schema_ext.sql 中 order_status_log、sys_operation_log 两段（可重复执行） |

### 3.2 mq 包结构（本轮新建，02§三预留位）
```
com.stocksim.mq
├── producer    DealMessageProducer（买/卖两条事务消息，order_no 分片键）
├── consumer    BuyDealConsumer / SellDealConsumer（顺序消费 + 幂等）
├── message     DealBookingMessage（dealNo/dealSeq/stockCode/price/qty/orderNo/userId/direction/tradeDate）
└── compensate  DealCompensateTask（扫已落库未记账 → 补发；死信告警日志）
```
`match/notify` 增加 `MqDealNotify implements DealNotify`（notify=mq 生效）；`SyncDealNotify` 保留（notify=sync，测试与降级演示用）。两侧记账逻辑从 SyncDealNotify 抽取为 `DealBookingService`（单侧：订单 CAS + 账户/持仓 + 双侧流水 + 日汇总），同步/异步两实现共用，**记账口径只有一份**。

### 3.3 common 新增组件

| 组件 | 要点 |
|------|------|
| `LockProvider` | Redisson 封装，三类 key：`lock:stock:{code}` / `lock:account:{userId}` / `lock:settlement:leader`；返回 `Lock`，看门狗自动续期；业务侧无 Redisson API |
| `@RateLimit` + 切面 | Redisson RRateLimiter，key=`rl:{type}:{userId}`，tryAcquire 失败 → 1004 |
| 审计切面 | `/api/admin/**` 写操作成功后落 sys_operation_log（Q9）；登录审计在 auth 内 |
| 缓存约定 | key/TTL/打散/失效统一在 stock service 读路径内（Q1），调用方无感 |

### 3.4 数据访问纪律
沿用 R1§3.4：流水只追加、金额 BigDecimal HALF_UP 到分、查询携带 userId、CHECK 约束违反即记账 bug（5001 + 告警，不绕过）。

### 4.2 实现级口径（文档未写死，本规划默认值）

| # | 口径 | 内容与理由 |
|---|------|-----------|
| Q1 | 缓存细节 | 行情 TTL 3s±随机打散（对齐刷新间隔）；股票信息 TTL 30min；**列表分页不缓存**（低频），单查缓存。布隆用 Redisson RBloomFilter（expectedInsertions=10000、误判率 0.01），启动全量初始化、新股加入；布隆判无 → 1001 不回源。Redis 故障：读路径捕获异常回源 DB，写路径锁失败 fail-fast |
| Q2 | 锁细节 | 全部 RLock 看门狗续期（不设 leaseTime）；tryLock 等待 3s：撮合/撤单超时 → 4002，账户超时 → 5001；选主锁 tryLock 0 等待，占用中 → 返回「清算执行中」。MatchEngine.lockOf 返回类型改 `Lock`，引擎代码零改动 |
| Q3 | 撤单核心 | 用户撤单/过期撤单共用一个撤单核心：股票锁 → **在途记账检查**（该单 Σdeal_record.deal_qty == order.matched_qty，不等 → 4002 可重试）→ 状态 CAS（1→4 / 2→5，其余 3007）→ 解冻剩余精确值（买 C4 / 卖 C5）→ 盘口移除 → 状态日志（type 2/3）。在途检查把「撤单与撮合互斥」延伸到异步记账窗口，杜绝解冻与扣款竞态 |
| Q4 | 事务消息编排 | 买/卖两条事务消息依次发送，本地事务执行器**幂等落 deal_record + 行情量额**（第一条插入、第二条确认存在即 COMMIT）；回查 = 按 dealNo 查 deal_record 存在性。发送失败走 MatchEngine 既有 ≤3 重试（换新 dealNo/seq）。崩溃窗口（只发出一条）由 Q7 补偿兜底 |
| Q5 | 消费细节 | order_no 作 MessageQueueSelector 分片键 → **同订单顺序消费**（买卖不同单天然并行）；消费事务复用 DealBookingService；重试上限（默认 5）耗尽 → 死信 + 告警日志；消费端 requireOpenOrder 校验保留作防御 |
| Q6 | 重建口径 | 启动重建剩余数量 = entrust_qty − **Σdeal_record.deal_qty**（权威，走 idx_buyer/seller_order_no），**不用 matched_qty**——异步下已落库未记账的成交不会二次入盘撮合；状态过滤与 deal_seq 恢复不变 |
| Q7 | 补偿任务 | @Scheduled fixedDelay 60s（可配）：扫近 N 分钟 deal_record，按侧比对日汇总/订单累计，缺记账 → 补发普通消息（消费幂等兜底）；同时扫死信队列告警日志。覆盖发送崩溃窗口、重试耗尽、死信三类异常；不用延迟消息（4.9.x 限制，02§二） |
| Q8 | 限流细节 | RateType.OVERALL 按用户维度：下单 5 次/秒、行情 20 次/秒（可配）；tryAcquire 0 等待失败 → 1004；全局开关 enabled；阈值热更新不做（改配置重启） |
| Q9 | 审计范围 | admin 登录成功（type 1）+ /api/admin/** 写操作成功（股票新增/修改/状态=2、手动刷新=3、日切=5）；切面 afterCompletion 落库，detail=请求摘要 JSON（密码脱敏）、ip=remoteAddr；**审计插入失败仅告警日志，不影响业务**；差错处理（4）第四轮预留 |
| Q10 | 状态日志 | 收敛进 casTransit 同事务写入（签名加 changeType/operatorId，全部调用方适配）：撮合记账=1、用户撤单=2、过期撤单=3；系统操作 operator 为空；清算=4 第四轮预留 |
| Q11 | 配置切换 | notify=sync|mq 默认 mq；测试 profile 固定 sync（147 测试零改动）；MQ 集成测试独立用例类走真实 broker |
| Q12 | 日切适配 | 三步流程不变；过期撤单改走 Q3 撤单核心（获得在途检查）；日切入口取选主锁；日切成功后删除全部行情缓存 |

## 五、里程碑与任务分解（WBS）

> 估算按单人专注开发计，总计 **约 9.5 人日（8–12）**。每里程碑独立 commit，DoD 不满足不进入下一里程碑；冒烟后还原种子、停应用（沿用第一轮验收节奏）。

| 里程碑 | 内容 | 依赖 | 估算 | 验收检查点 |
|--------|------|------|------|-----------|
| M0 | 环境 + 工程底座 | 无 | 0.5d | MQ 收发一条消息、Redis PONG、两扩展表建成、应用启动（sync）、147 绿 |
| M1 | Redis 缓存 + 布隆 | M0 | 1d | 命中/回源/失效/布隆拒绝；停 Redis 行情可读；对账零差异 |

| M3 | 撤单 + 状态日志 | M2 | 1.5d | 撤单用例全过（含在途 4002）；状态日志全类型；对账零差异 |
| M4 | MQ 异步记账 | M3 | 3d | §6.3 数值核对；重放/重启/回查/补偿用例；三条 SQL 零差异；sync 回归绿 |

| M6 | 集成验收 + 归档 | M1–M5 | 1.5d | §7.3 B1–B16 全过；A 系列核心复验；验收记录归档 |

### M0 环境 + 工程底座（0.5d）
- 交付：rocketmq-compose.yml 并启动；执行两张扩展表 DDL；pom 两依赖；application.yml 配置骨架（密钥占位）；LockProvider/缓存/限流空壳 Bean 不接业务。
- 要点：**先向用户索取 MySQL root 密码**；broker 配置见 §3.1（brokerIP1/堆/端口）；notify 先置 sync 保证基线不变。
- DoD：`docker compose ps` 两容器健康；测试消息收发成功；两表建成；`mvn test` 147 绿；应用启动 Knife4j 可访问。

### M1 Redis 缓存 + 布隆（1d）
- 交付：QuoteService/StockService 读路径缓存（Q1）；刷新/管理端变更/日切后失效；RBloomFilter 初始化与新股加入；Redis 故障读降级。
- DoD：连续查询命中（日志验证）；刷新后读到新值；不存在代码被布隆拒绝不回源；停 Redis 行情查询仍可用；三条对账 SQL 零差异（缓存不影响权威数据）。

### M2 Redisson 三锁（1d）
- 交付：LockProvider；MatchEngine/Settlement 股票锁替换（lockOf 返回 Lock）；账户变动统一入口叠加账户锁；日切入口选主锁。
- 要点：锁内事务边界不变（先锁后事务）；账户锁与 version CAS 叠加不互替。
- DoD：147 绿；并发入金/出金/下单冒烟无超扣（CHECK 零违反）；并发触发日切一个执行一个拒绝；停 Redis 下单/撤单 5001、行情可读。

### M3 用户撤单 + order_status_log（1.5d）
- 交付：撤单核心（Q3）+ `POST /api/orders/{orderNo}/cancel`；casTransit 收敛状态日志（Q10）；日切过期撤单改走撤单核心。
- 要点：属主校验（非本人 1003）；在途检查读 deal_record 权威；解冻剩余精确值零残留；reject_reason=用户撤单。
- DoD：B2–B6 全过；order_status_log 覆盖撮合/用户撤单/过期撤单三类；对账零差异。

### M4 RocketMQ 异步记账（3d，本轮难度最高）
- 交付：DealBookingService 抽取；MqDealNotify + DealMessageProducer（Q4）；买/卖消费者（Q5）；重建口径切换（Q6）；DealCompensateTask（Q7）；notify 开关（Q11）。
- 要点：事务消息本地执行器幂等；回查只查 DB 不查内存；顺序消费分片键 order_no；消费失败重试上限→死信告警；补偿任务与消费幂等互为兜底。
- DoD：异步买卖链路 §6.3 数值逐项核对；重放消息流水不重复；kill 消费者→重启→记账补齐；回查用例（模拟 UNKNOWN）正确 COMMIT/ROLLBACK；补偿用例；三条对账 SQL 零差异；切回 sync 147 绿。

## 六、关键实现细节（开发时逐条核对）

### 6.1 异步链路时序
```
下单 T1（不变：校验+冻结+双侧流水）
 └─ afterCommit → MatchEngine.onNewOrder（股票锁 RLock）
     └─ 每笔成交：
         发事务消息 BUY ─ 本地事务 T2'：deal_record + 行情量额（幂等）─ COMMIT
         发事务消息 SELL ─ 本地执行器确认 deal_record 存在 ─ COMMIT
         发送成功 → 盘口 reduce、dealSeq.commit（失败 ≤3 重试换新 dealNo/seq）
消费端（order_no 顺序消费，买/卖两组）：
 BUY  → T3b：订单 CAS + 扣款 B5 + 佣金 B7 + 增仓 B1 + 日汇总 upsert
 SELL → T3s：订单 CAS + 减仓解冻 S2 + 入账 S6 + 佣金印花税 S7 + 日汇总 upsert
 失败重试 ≤ 上限 → 死信 + 告警；补偿任务扫描兜底
```
严禁：盘口先扣减后发消息；回查依赖内存状态；消费端跨用户合并事务（第三轮跨库即失效）。

### 6.2 撤单与在途记账互斥（数值例）
买 200 股 @10.00，冻结 2005.00。成交 100 股 @9.80 已落 deal_record 未记账：
- 此刻撤单：Σdeal_qty=100 > matched_qty=0 → **4002 可重试**（不撤）；
- 消费完成后 matched=100、frozen=1002.50 → 撤单成功：解冻剩余精确值 1002.50（C4），状态 2→5，冻结零残留 ✓。
若无在途检查：撤单解冻全部 2005 → 消费者再解冻 → frozen 为负 → CHECK 拒绝 → 死信。此即 Q3 的必要性。

### 6.3 异步记账数值例（与 R1§6.4 同值，异步模式复验）
user02 先挂卖 100 @9.90，user01 后挂买 100 @10.10 → 成交 @9.90：
- T2'：deal_record（qty=100、amount=990.00）+ 行情量 +100 / 额 +990.00；
- BUY 消息：user01 扣 990（B5）+ 佣金 5（B7），持仓 100、today_buy=100（B1），日汇总 +100/+990/+5；
- SELL 消息：user02 持仓 900（S2）、入 990−5.50=984.50（S6+S7），日汇总 +100/+990/+5.50；
- 三条对账 SQL 零差异；order_status_log 两条（1→3，type 1）。

### 6.4 幂等与重放矩阵

| 场景 | 拦截点 | 结果 |
|------|--------|------|
| 买/卖消息重复消费 | uk_flow_no（{deal_no}B5/B7/B1/S6/S7/S2） | 事务整体回滚，不重复记账 |
| 事务回查 | deal_record by deal_no 存在性 | COMMIT / ROLLBACK |
| 补偿补发 | 同重复消费 | 幂等 |
| 重复撤单请求 | 状态 CAS（4/5 不可再迁移） | 3007 |
| 重复下单/入金/出金 | uk_user_request（不变） | 返回原单/原流水 |
| 重启重建 | Q6 deal_record 口径 | 在途成交不二次撮合 |

### 6.5 缓存 key 与失效约定
`quote:{code}`（TTL 3s±打散）、`stock:{code}`（30min）、`bloom:stock`。失效时机：refreshOne 成功、管理端股票变更、日切完成（全量删行情缓存）。列表分页直查 DB。缓存仅加速，任何不一致以 MySQL + 对账兜底。

### 6.6 RocketMQ 部署要点
brokerIP1=127.0.0.1（否则客户端拿到容器内网 IP 连不上）；端口 9876/10911/10909 映射；topic `STOCKSIM_DEAL_BOOKING`（tag BUY/SELL），消费组 `stocksim-buy-consumer` / `stocksim-sell-consumer` 各订一个 tag；死信 `%DLQ%{消费组}`；broker 堆 512m、namesrv 默认 256m 内。

### 7.4 对账 SQL
R1§7.4 三条（资金/持仓/订单-日汇总）不变，新增第四条（单库版权威交叉核对，第三轮移离线）：
```sql
-- 成交权威明细 vs 订单成交日汇总
SELECT o.order_no,
       COALESCE(SUM(r.deal_qty),0)  AS record_qty,
       COALESCE(MAX(d.deal_qty),0)  AS daily_qty
FROM trade_order o
LEFT JOIN deal_record r
  ON r.buyer_order_no = o.order_no OR r.seller_order_no = o.order_no
LEFT JOIN deal_order_daily d
  ON d.user_id = o.user_id AND d.order_no = o.order_no
GROUP BY o.order_no
HAVING record_qty <> daily_qty;
```
另抽查 order_status_log：每笔终态订单最新日志 to_status = trade_order.status。

### 7.5 性能口径
本轮不压测（第四轮 JMeter）。热路径纪律：撮合循环内除锁获取外无 Redis IO（锁在循环外持有）；消费端 DB 操作与同步版等量；缓存命中路径不回源。
