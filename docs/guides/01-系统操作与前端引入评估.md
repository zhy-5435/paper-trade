# 系统操作指南与前端引入评估报告

> 本报告分两部分：**第一部分**说明当前系统如何使用、以纯 HTTP 手动跑通全部业务链路（事实依据为已验收的端点与 DTO，链路已在 [第一轮集成验收记录](../rounds/round1/02-集成验收记录.md) A1–A18 中端到端验证）；**第二部分**评估是否引入前端以便操作，给出选项对比、推荐方案与决策清单。
> 适用版本：第一轮（单库基础业务，已验收）。报告内所有地址均为本机 `http://localhost:8080`。

---

## 结论速览（TL;DR）

- **当前完全可用**：系统已自带 Knife4j 交互式接口文档（`/doc.html`），配合 curl/HTTP 脚本即可手动跑通"注册→入金→行情→下单→撮合→成交→持仓→日切→对账"全链路，无需前端即可演示与验收。
- **前端不是必需品，而是演示增强项**：后端才是本项目的面试差异化重点（一致性、撮合、分布式演进）。前端的核心价值是"让演示更直观"，而非补齐功能缺口。
- **推荐分阶段**：
  1. **零成本基线（建议立即做）**：沉淀一份可复现的 API 集合（Bruno/Postman/Apifox）+ 本报告附录的一键演示脚本，解决"多角色 token、requestId 幂等、orderNo 跟踪"的手工负担。
  2. **可选增强（若需可视化面试演示）**：引入**极简 SPA**（Vue3 + Vite + Element Plus，独立模块/仓库，约 3–5 人日），仅覆盖核心链路，轮询取数；**不做**完整前端产品。
  3. **实时盘口/K 线/WebSocket 推送**留待第二/三轮（Redis/RocketMQ 接入后）再升级，形成"单库轮询 → 分布式实时推送"的演进叙事。
- **决策口径**：当"需要面向面试官做可视化_live 演示"且"后端轮次进度允许"时引入极简 SPA；否则 Knife4j + API 集合已足够。

# 第一部分 · 系统使用与手动全链路操作指南

## 1. 使用前提

### 1.1 环境与启动

- 环境：JDK 21 · Maven 3.8+ · MySQL 8.0（本地）。
- 初始化库：`CREATE DATABASE stock_sim`，依次执行 `sql/schema.sql`（核心 13 表）、`sql/seed.sql`（演示种子）。`sql/schema_ext.sql` 为后续轮次扩展表，第一轮可不执行。
- 密钥：项目根 `application-local.yml`（已 gitignore）配置 `spring.datasource.password` 与 `stocksim.jwt.secret`（≥32 字节），或用环境变量 `MYSQL_PASSWORD` / `JWT_SECRET`。
- 启动：`mvn spring-boot:run`，监听 `http://localhost:8080`。
- 验收/演示建议冻结行情刷新以保证确定性：
  ```bash
  mvn spring-boot:run -Dspring-boot.run.arguments=--stocksim.quote.refresh-interval-ms=3600000
  ```

### 1.2 演示账号（种子）

| 账号 | 密码 | 角色 | 说明 |
|------|------|------|------|
| admin | admin123 | 2（管理员） | 股票/行情/日切管理 |
| user01 | 123456 | 1（普通） | 买方演示 |
| user02 | 123456 | 1（普通） | 卖方演示，持初始持仓 600000×1000 + 000007×100（today_buy=0，即日可卖） |

### 1.3 通用约定

- **统一返回**：HTTP 200 + `Result{code, message, data}`，`code=0` 成功，非 0 为业务错误码。
- **鉴权**：除 `/api/auth/register`、`/api/auth/login` 外，所有 `/api/**` 需请求头 `Authorization: Bearer <token>`；`/api/admin/**` 额外要求 `role=2`。无 token→`1002`，非管理员→`1003`。
- **数据类型**：金额（BigDecimal）序列化为**字符串**（如 `"990.00"`），比较时按数值处理；时间格式 `yyyy-MM-dd HH:mm:ss.SSS`，时区 Asia/Shanghai。
- **分页**：`PageResult{records, total, page, size}`，查询参数 `page`（默认 1）、`size`（默认 10）。
- **幂等**：入金/出金/下单均带 `requestId`，重复提交返回首次结果，不重复扣划/冻结。

### 1.4 第一轮交互限制（影响操作方式，务必知悉）

| 限制 | 说明 | 操作影响 |
|------|------|----------|
| 下单返回**撮合前快照** | 撮合在事务提交后（afterCommit）同步执行，创建接口返回时状态仍为 `1 PENDING` | 下单后需**重新 GET** `/api/orders/{orderNo}` 获取真实状态 |
| 成交价 = resting 挂单价 | 以更早挂单（createTime，orderId 兜底）的价格成交 | 想验证特定成交价，需先挂对手单 |
| **无用户撤单接口** | 主动撤单属第二轮 | 挂单只能等待成交或由**日切**过期（→6） |
| **无实时推送** | 行情默认 3s 定时刷新 + 管理端手动刷新 | 客户端需**轮询**行情/订单/持仓 |
| 仅限价单 | orderType=1，市价单为选做未实现 | 下单必须带 price |
| 无管理端对账/批次接口 | 清算批次/资产快照/对账差异属第四轮 | 对账用 **SQL 直查**（见 §3.9） |
| 默认不校验交易时段 | `session-check-enabled=false` | 任意时刻可下单（演示友好） |

## 2. 端点总览

### 2.1 公开（无需 token）

| 方法 | 路径 | 用途 | 请求体 |
|------|------|------|--------|
| POST | `/api/auth/register` | 注册（自动开户） | `{username, password, nickname?, phone?, email?}` |
| POST | `/api/auth/login` | 登录签发 JWT | `{username, password}` |

### 2.2 用户端（需 Bearer token）

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/user/profile` | 个人信息 |
| PUT | `/api/user/profile` | 修改资料 `{nickname?, phone?, email?}` |
| GET | `/api/account` | 余额/冻结/可用/总资产（总资产=余额+持仓实时市值） |
| POST | `/api/account/deposit` | 入金 `{requestId, amount}` |
| POST | `/api/account/withdraw` | 出金 `{requestId, amount}` |
| GET | `/api/account/flows?page&size&flowType` | 资金流水（flowType：1=入金、2=出金，其余为交易/冻结解冻内部流水） |
| GET | `/api/positions` | 持仓列表（实时市值/浮盈/可卖） |
| GET | `/api/positions/flows?page&size&stockCode` | 持仓流水 |
| GET | `/api/stocks?page&size` | 股票分页列表 |
| GET | `/api/stocks/{code}` | 股票详情 |
| GET | `/api/stocks/{code}/quote` | 单只行情 |
| GET | `/api/quotes?codes=600000,000001` | 批量行情 |
| POST | `/api/orders` | 创建限价单 `{requestId, stockCode, direction, price, quantity}` |
| GET | `/api/orders?page&size&status&startTime&endTime` | 我的订单分页 |
| GET | `/api/orders/{orderNo}` | 订单详情 |
| GET | `/api/deals?page&size&stockCode` | 我的成交分页 |

### 2.3 管理端（需 Bearer token + role=2）

| 方法 | 路径 | 用途 | 请求体 |
|------|------|------|--------|
| POST | `/api/admin/stocks` | 新增股票（自动初始化当日行情） | `{stockCode, stockName, market(1-3), boardType(1-4), issuePrice, priceLimitRatio(0.01-0.50), lotSize?, listDate?}` |
| PUT | `/api/admin/stocks` | 修改股票 | `{stockCode, stockName?, market?, boardType?, priceLimitRatio?, lotSize?, listDate?}` |
| PUT | `/api/admin/stocks/{code}/status` | 停牌/复牌/退市 | `{status}`（1=正常/0=停牌，退市见状态口径） |
| POST | `/api/admin/quotes/refresh` | 手动刷新全部行情 | 无（返回刷新只数） |
| POST | `/api/admin/settlement/run` | 最小日切（幂等可重跑） | 无 |

### 2.4 关键枚举

- **direction**：1=买，2=卖。
- **订单 status**：1=待成交 PENDING，2=部分成交 PARTIAL_FILLED，3=全部成交 FILLED，4=已撤单 CANCELED，5=部分撤单 PARTIAL_CANCELED，6=日切过期 EXPIRED。（第一轮无撤单接口，4/5 暂不可达；日切驱动 →6。）
- **常见错误码**：1001 参数/重复、1002 未登录、1003 无权限、2001 余额不足、2003 持仓不足、3001 涨跌停、3002 非整手、3003 T+1、3004 停牌、5001 系统繁忙（CAS 冲突）。

## 3. 手动全链路操作（curl 示例）

> 约定：`BASE=http://localhost:8080`。示例用 `jq` 提取字段（无 jq 时手动复制 token/orderNo 即可）。所有非 auth 请求都要带 `Authorization: Bearer`。

### 3.1 注册 + 登录（取 token）

```bash
BASE=http://localhost:8080
# 注册新用户（自动开户，余额 0）
curl -s -X POST $BASE/api/auth/register -H 'Content-Type: application/json' \
  -d '{"username":"demo01","password":"123456","nickname":"演示01"}'
# 登录取 token（演示直接用种子账号）
T1=$(curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"user01","password":"123456"}' | jq -r .data.token)
T2=$(curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"user02","password":"123456"}' | jq -r .data.token)
TA=$(curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | jq -r .data.token)
```
预期：`code=0`，`data.token` 为 JWT，`data.role` 区分 1/2。

### 3.2 入金 / 出金（幂等）

```bash
# user01 入金 100000（requestId 幂等键）
curl -s -X POST $BASE/api/account/deposit -H "Authorization: Bearer $T1" \
  -H 'Content-Type: application/json' -d '{"requestId":"dep-001","amount":100000}'
# 重复同一 requestId：余额不变（幂等）
curl -s -X POST $BASE/api/account/deposit -H "Authorization: Bearer $T1" \
  -H 'Content-Type: application/json' -d '{"requestId":"dep-001","amount":100000}'
# 查账户与资金流水
curl -s $BASE/api/account -H "Authorization: Bearer $T1"
curl -s "$BASE/api/account/flows?flowType=1&size=5" -H "Authorization: Bearer $T1"
# user02 入金（对手盘资金）
curl -s -X POST $BASE/api/account/deposit -H "Authorization: Bearer $T2" \
  -H 'Content-Type: application/json' -d '{"requestId":"dep-002","amount":100000}'
```
预期：入金后 `balance="100000.00"`；超额出金返回 `2001`。

### 3.3 行情查询（需 token）

```bash
curl -s $BASE/api/stocks/600000/quote -H "Authorization: Bearer $T1"
curl -s "$BASE/api/quotes?codes=600000,000001" -H "Authorization: Bearer $T1"
# 管理端手动刷新全部行情
curl -s -X POST $BASE/api/admin/quotes/refresh -H "Authorization: Bearer $TA"
```
关注：`tradeDate`、`latestPrice`、`limitUpPrice/limitDownPrice`（下单价须在涨跌停内）。

### 3.4 下单（限价，幂等）

```bash
# user02 先挂卖单 100@9.90（resting，成为成交价基准）
S=$(curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T2" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"sell-001","stockCode":"600000","direction":2,"price":9.90,"quantity":100}')
echo "$S" | jq .data.orderNo
# user01 挂买单 100@10.10 → 立即与卖单撮合，成交价=9.90（resting 价）
B=$(curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T1" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"buy-001","stockCode":"600000","direction":1,"price":10.10,"quantity":100}')
BNO=$(echo "$B" | jq -r .data.orderNo)
```
**注意**：创建响应是撮合前快照（status=1）。需重新查询真实状态：
```bash
curl -s $BASE/api/orders/$BNO -H "Authorization: Bearer $T1"   # 期望 status=3 FILLED
```
校验链失败示例（返回对应错误码，不落库）：价超涨跌停 `3001`、买非整手 `3002`、停牌 `3004`、余额不足 `2001`、可卖不足 `2003`、当日买当日卖 `3003`。

### 3.5 成交 / 持仓 / 资金核对

```bash
curl -s "$BASE/api/deals?stockCode=600000&size=5" -H "Authorization: Bearer $T1"
curl -s $BASE/api/positions -H "Authorization: Bearer $T1"
curl -s $BASE/api/account -H "Authorization: Bearer $T1"
```
预期（卖先挂@9.90、买 100 成交）：
- 买方 user01：成交额 990，佣金 max(5, 990×0.00025)=5 → 成本 995，余额 100000−995=**99005**；持仓 600000 +100，`todayBuyQty=100`（当日不可卖）。
- 卖方 user02：成交额 990，费用 min(5+990×0.0005, 990)=5.50 → 净额 **984.50**；持仓 600000 −100。
- 成交 `dealSeq` 全局单调递增。

> 费用口径：佣金=max(5, 成交额×0.00025)（买卖均收）；印花税=成交额×0.0005（仅卖出）；卖出总费用=min(佣金+印花税, 成交额)（封顶，零股净额≥0）；金额四舍五入到分（HALF_UP）。

### 3.6 T+1 验证

```bash
# user01 当日买入的 100 股当日再卖 → 3003
curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T1" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"sell-t1","stockCode":"600000","direction":2,"price":9.90,"quantity":100}'
```

### 3.7 管理端：停牌 / 复牌 / 新增股票

```bash
# 停牌 000001（status=0）→ 对其下单返回 3004
curl -s -X PUT $BASE/api/admin/stocks/000001/status -H "Authorization: Bearer $TA" \
  -H 'Content-Type: application/json' -d '{"status":0}'
# 复牌
curl -s -X PUT $BASE/api/admin/stocks/000001/status -H "Authorization: Bearer $TA" \
  -H 'Content-Type: application/json' -d '{"status":1}'
# 新增股票（自动初始化当日行情）
curl -s -X POST $BASE/api/admin/stocks -H "Authorization: Bearer $TA" \
  -H 'Content-Type: application/json' \
  -d '{"stockCode":"600519","stockName":"演示茅台","market":1,"boardType":1,"issuePrice":100.00,"priceLimitRatio":0.10,"lotSize":100}'
```

### 3.8 管理端：最小日切（核心）

```bash
curl -s -X POST $BASE/api/admin/settlement/run -H "Authorization: Bearer $TA" | jq .data
```
预期 `SettlementResult`：
```json
{"expiredOrders":2,"cutQuotes":5,"clearedPositions":1,"closeDate":"2026-11-13","nextDate":"2026-11-16"}
```
日切三步效果：
1. **过期撤单解冻**：未成交/部分成交挂单 → `status=6 EXPIRED` + `rejectReason="日切过期撤单"`，买单解冻资金（C4）、卖单解冻持仓（C5），盘口移除。
2. **行情日切**：`pre_close=日切前 latest`，按新 pre_close 重算涨跌停，`open/high/low=NULL`，量额清零，`trade_date` 推进到次一交易日。
3. **today_buy 清零**：持仓 `todayBuyQty=0` → 次日可卖（T+1 闭环）。

日切后验证次日卖出（user01 卖昨日买入的 100 股，应受理）：
```bash
curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T1" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"sell-next","stockCode":"600000","direction":2,"price":9.90,"quantity":100}'
```
> 幂等说明：日切按"当前行情 trade_date"推导 D，**每次运行都会推进一天**；同一 D 内的重复执行由 WHERE/CAS 守卫保证不重复处理（非"连跑两次完全无操作"）。

### 3.9 对账（SQL 直查，第一轮无管理端对账接口）

三条对账 SQL（资金/持仓/订单）见 [第一轮集成验收记录 §四](../rounds/round1/02-集成验收记录.md)，均 should 返回 **0 行**。本地执行：
```bash
mysql -uroot stock_sim   # 粘贴 R1验收 §四 的三条 SQL
```

### 3.10 重启重建验证（可选）

重启应用后，未成交挂单从 DB 重建盘口、`deal_seq` 从全局 MAX 恢复（不回退）。日志可见 `盘口重建完成: 挂单 N 笔, dealSeq=M`。重启后对重启前挂单继续撮合，新成交 `dealSeq=M+1`。

## 4. 当前操作方式的痛点（前端评估的输入）

1. **多角色多 token**：买方/卖方/管理员需分别登录、保存与切换 token，手工易错。
2. **幂等键与单号跟踪**：requestId 需手工保证唯一；orderNo 需在多步间传递。
3. **状态需轮询**：下单返回撮合前快照，行情/订单/持仓变化都要反复 GET，JSON 不直观。
4. **盘口不可见**：内存 OrderBook 无查询端点，挂单深度/排队只能靠订单列表间接推断。
5. **管理操作分散**：日切、停牌、刷新、新增股票分散在多个端点，演示时切换成本高。
6. **对账靠 SQL**：无可视化对账面板，需切到数据库客户端。
7. **演示叙事弱**：面对面试官展示一堆 JSON，远不如"下单→盘口→成交→持仓浮盈→一键日切"的可视化面板有说服力。

# 第二部分 · 前端引入评估

## 5. 需求分析

### 5.1 使用者与场景

| 场景 | 使用者 | 诉求 | 前端必要性 |
|------|--------|------|-----------|
| 开发自测 / 验收复现 | 开发者（本人） | 快速跑通链路、断言结果 | 低（Knife4j + 脚本已足够） |
| 面试 live 演示 | 面试官观看 | 直观看到交易闭环、一致性、日切 | **高**（可视化显著加分） |
| 功能探索 / 回归 | 本人 / 他人 | 点选式操作各端点 | 中（Knife4j 可点选，但无业务编排） |

### 5.2 核心判断

- 本项目定位是**后端演示系统**，面试差异化在"金融级一致性 + 撮合引擎 + 分布式演进"，**前端不是能力信号的核心**。
- 但"可运行的完整系统"比"一堆接口"更有说服力；一个**极简交易面板**能把抽象的一致性/撮合/日切变成可见的交互，放大后端亮点的呈现效果。
- 因此前端应定位为**演示增强（demo aid）**，严格控范围，避免喧宾夺主与范围蔓延。

## 6. 现有替代方案：Knife4j 已提供交互式 UI

- 启动后访问 `http://localhost:8080/doc.html`，Knife4j（OpenAPI3）已自动聚合全部端点，支持在线填参、发送、查看响应、Bearer 鉴权头配置。
- 这已经是一个"零额外成本"的操作界面，能覆盖单端点调试。
- **不足**：无业务编排（多步链路仍需手工串联）、无 token/单号自动管理、无盘口/持仓可视化、无一键日切面板。

> 结论：Knife4j 解决了"有没有 UI"，没解决"演示好不好看、链路顺不顺"。前端评估的真正问题是"是否值得为演示体验额外投入"。

## 7. 选项对比

| 选项 | 描述 | 一次性成本 | 演示效果 | 维护负担 | 与后端聚焦契合 | 主要风险 |
|------|------|-----------|---------|---------|---------------|---------|
| **A 不引入** | 沿用 Knife4j + curl | 0 | 弱（JSON） | 无 | 最高 | 演示叙事弱 |
| **B API 集合 + 脚本** | Bruno/Postman/Apifox 集合 + 环境变量 + 预置链路 + 一键脚本 | 0.5–1 人日 | 中（可复现，仍非可视） | 低 | 高 | 仍无视觉面板 |
| **C 极简 SPA** | Vue3/React 单页，覆盖核心链路，轮询取数，独立模块 | 3–5 人日 | **强**（交易面板） | 中 | 中（需克制范围） | 范围蔓延、与后端轮次争时间 |
| **D SSR 轻量页** | Thymeleaf/htmx + 少量 JS，服务端渲染 | 2–3 人日 | 中强 | 中 | 中 | 交互上限低、与 REST 风格略割裂 |
| **E 完整前端产品** | 实时盘口/K线/WebSocket/复杂风控配置 | 15+ 人日 | 很强 | 高 | 低 | 严重喧宾夺主，过度工程 |

## 8. 推荐方案（分阶段、可回退）

### 阶段 0（立即，零成本）：沉淀可复现操作资产
- 将第一部分链路固化为 **API 集合**（推荐 Bruno/Apifox，纯文本可入库）+ 附录一键演示脚本。
- 价值：解决多 token/requestId/orderNo 手工负担，演示与验收可一键复现，**不写任何前端代码**。

### 阶段 1（可选，若需可视化面试演示）：极简 SPA（选项 C）
- **定位**：演示增强，独立目录/仓库（如 `web/` 或单独 repo），不污染后端工程与分层。
- **范围（只做这些）**：
  - 登录页（user/admin 切换，token 自动管理）。
  - 行情列表 + 下单面板（买/卖、价/量、涨跌停提示、requestId 自动生成）。
  - 持仓 & 资金卡片（余额/冻结/可用/总资产/浮盈，轮询刷新）。
  - 订单 & 成交列表（状态徽标，下单后自动重查真实状态）。
  - 管理端面板（一键日切、停牌/复牌、手动刷新行情、新增股票）。
  - 对账只读视图（可选：后端加一个只读对账汇总端点，或前端展示三条 SQL 结果）。
- **技术选型**：Vue3 + Vite + Element Plus（或 React + Ant Design）+ axios；**轮询**取数（第一轮无推送）；开发期 Vite 代理 `/api` 到 8080 规避 CORS，生产可同源部署或后端开 CORS。
- **明确不做**：WebSocket 实时盘口、K 线/分时、复杂风控配置、用户撤单（后端第二轮才有）、多端适配。
- **估算**：3–5 人日（脚手架 0.5 + 登录/行情/下单 1.5 + 持仓资金/订单成交 1 + 管理面板 1 + 联调打磨 0.5–1）。

### 阶段 2（后续轮次）：实时化升级
- 第二/三轮接入 Redis/RocketMQ 后，把轮询升级为 **WebSocket/SSE 实时推送**（成交、盘口、行情），新增只读盘口深度视图。
- 形成"单库轮询 → 分布式实时推送"的演进叙事，前端成为后端架构升级的**展示窗口**，而非独立负担。

### 不推荐：选项 E（完整前端产品）
- 与"后端面试演示"定位冲突，投入产出比低，挤占后端轮次（真正的差异化）时间。

## 9. 与四轮路线的契合 / 时机

| 轮次 | 后端重点 | 前端动作建议 |
|------|---------|-------------|
| 第一轮（已完成） | 单库基础业务 + 验收 | 阶段 0（API 集合/脚本）；如需演示可做阶段 1 极简 SPA（轮询版） |
| 第二轮 | Redis / RocketMQ / 撤单 / 操作审计 | SPA 增加撤单按钮、实时推送（WebSocket）、操作审计视图 |
| 第三轮 | 分库分表 / 主从 | 前端无感（后端透明），可加"分片路由"只读演示页 |
| 第四轮 | 清算对账 / 压测 | SPA 增加对账面板、批次/快照视图、压测指标看板 |

**时机建议**：若面试临近且需要 live 演示，先做阶段 0 + 阶段 1（轮询版）即可形成完整可视化闭环；实时推送随第二轮自然升级，避免一次性过度投入。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 范围蔓延（越做越像完整产品） | 严格锁定 §8 阶段 1 范围清单；"不做"项写入 README；按页面验收 |
| 挤占后端轮次时间 | 前端独立模块/仓库，限定 3–5 人日预算；后端轮次优先 |
| 前后端联调/CORS/鉴权成本 | 开发期 Vite 代理同源；token 统一拦截器注入；复用 Knife4j 契约 |
| 轮询体验/性能 | 合理轮询间隔（2–3s）+ 页面可见时才轮询；第二轮升级推送 |
| 演示数据脏乱 | 提供"一键重置种子"脚本（TRUNCATE + seed），演示前还原 |
| 前端掩盖后端深度 | 演示脚本同时展示对账 SQL、CAS 重试日志、deal_seq 单调等后端硬证据 |

## 11. 决策清单（何时引入前端）

满足以下**任一**即建议引入极简 SPA（阶段 1）：
- [ ] 需要面向面试官做**可视化 live 演示**，而非仅接口讲解。
- [ ] 希望系统呈现为"完整可交易产品"以提升整体观感。
- [ ] 后端第一轮已稳定（已满足），且有 3–5 人日预算。

否则维持 **Knife4j + API 集合/脚本（阶段 0）** 即可，把精力投入第二/三/四轮后端差异化。

**最终建议**：先落地阶段 0（零成本、立即提升可复现性）；把阶段 1 极简 SPA 作为"面试演示可选增强"，在时间允许时投入；坚决不做选项 E。前端服务于后端亮点的呈现，不反客为主。

## 附录 A · 一键全链路演示脚本（bash + curl + jq）

> 仅访问本机 `http://localhost:8080`。演示前建议冻结行情刷新并还原种子。依赖 `jq`（无 jq 可改用手动复制）。

```bash
#!/usr/bin/env bash
set -euo pipefail
BASE=http://localhost:8080
login(){ curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d "{\"username\":\"$1\",\"password\":\"$2\"}" | jq -r .data.token; }
TA=$(login admin admin123); T1=$(login user01 123456); T2=$(login user02 123456)
auth(){ curl -s -H "Authorization: Bearer $1" "${@:2}"; }

echo "== 入金 =="
curl -s -X POST $BASE/api/account/deposit -H "Authorization: Bearer $T1" -H 'Content-Type: application/json' -d '{"requestId":"demo-dep-1","amount":100000}' | jq -c .code
curl -s -X POST $BASE/api/account/deposit -H "Authorization: Bearer $T2" -H 'Content-Type: application/json' -d '{"requestId":"demo-dep-2","amount":100000}' | jq -c .code

echo "== 卖先挂@9.90，买吃单@10.10 → 成交@9.90 =="
curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T2" -H 'Content-Type: application/json' -d '{"requestId":"demo-sell-1","stockCode":"600000","direction":2,"price":9.90,"quantity":100}' >/dev/null
BNO=$(curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T1" -H 'Content-Type: application/json' -d '{"requestId":"demo-buy-1","stockCode":"600000","direction":1,"price":10.10,"quantity":100}' | jq -r .data.orderNo)
auth $T1 $BASE/api/orders/$BNO | jq '{status,matchedQty,entrustPrice}'
auth $T1 "$BASE/api/deals?stockCode=600000&size=1" | jq '.data.records[0]|{dealPrice,dealQty,dealSeq}'
auth $T1 $BASE/api/account | jq '{balance,frozenAmount}'
auth $T1 $BASE/api/positions | jq '.data[]|select(.stockCode=="600000")|{totalQty,todayBuyQty,availableQty}'

echo "== T+1：当日买当日卖应 3003 =="
curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T1" -H 'Content-Type: application/json' -d '{"requestId":"demo-sell-t1","stockCode":"600000","direction":2,"price":9.90,"quantity":100}' | jq -c .code

echo "== 管理端日切 =="
auth $TA -X POST $BASE/api/admin/settlement/run | jq .data
auth $T1 $BASE/api/positions | jq '.data[]|select(.stockCode=="600000")|{todayBuyQty,availableQty}'

echo "== 次日卖出闭环 =="
curl -s -X POST $BASE/api/orders -H "Authorization: Bearer $T1" -H 'Content-Type: application/json' -d '{"requestId":"demo-sell-next","stockCode":"600000","direction":2,"price":9.90,"quantity":100}' | jq -c .code
echo "完成。对账请执行 R1验收 §四 三条 SQL（应 0 行）。"
```

## 附录 B · 端点—DTO 速查

- 注册 `RegisterRequest{username(3-50), password(6-64), nickname?, phone?(^1\d{10}$), email?}`。
- 登录 `LoginRequest{username, password}` → `LoginResponse{token, userId, username, role, nickname}`。
- 资金 `MoneyRequest{requestId(≤64), amount(≥0.01, 2 位小数)}`。
- 下单 `CreateOrderRequest{requestId(≤64), stockCode(6 位数字), direction(1/2), price(≥0.01, 4 位小数), quantity(≥1)}` → `OrderResponse{orderNo, stockCode, direction, orderType, entrustPrice, entrustQty, matchedQty, matchedAmount, frozenAmount, frozenQty, feeAmount, status, tradeDate, expireTime, rejectReason, createTime}`。
- 持仓 `PositionResponse{stockCode, totalQty, frozenQty, todayBuyQty, availableQty, costAmount, avgCostPrice, latestPrice, marketValue, floatingPnl, pnlRatio}`。
- 成交 `DealResponse{dealNo, stockCode, direction, orderNo, dealPrice, dealQty, dealAmount, dealSeq, dealTime}`。
- 行情 `QuoteResponse{stockCode, tradeDate, preClosePrice, openPrice, latestPrice, highPrice, lowPrice, limitUpPrice, limitDownPrice, totalVolume, totalAmount, changeRatio, quoteTime}`。
- 账户 `AccountResponse{accountNo, currency, balance, frozenAmount, availableAmount, totalAsset, status}`。
- 日切 `SettlementResult{expiredOrders, cutQuotes, clearedPositions, closeDate, nextDate}`。
- 股票 `CreateStockRequest{stockCode, stockName, market(1-3), boardType(1-4), issuePrice, priceLimitRatio(0.01-0.50), lotSize?, listDate?}`；`UpdateStockStatusRequest{status}`。
