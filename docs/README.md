# 文档导航与归档约定

> 本目录按四组管理：**design** 设计基线（跨轮次权威口径）、**rounds** 轮次档案（每轮规划 + 验收）、**guides** 操作指南与评估报告、**appendix** 知识扩展。
> 冲突处理：设计基线为权威口径；轮次规划与设计不一致时以设计为准，设计未写死的实现级空白按轮次规划执行。

## 目录结构

```
docs/
├── design/          设计基线：01–06，编号冻结，跨轮次权威口径
├── rounds/          轮次档案：每轮一个子目录，目录内独立编号
│   ├── round1/      01-开发规划、02-集成验收记录（已验收）
│   └── round2/      01-开发规划、02-集成验收记录（已验收）、03-开发过程记录
├── guides/          操作指南与评估报告：目录内独立编号（当前 01）
└── appendix/        知识扩展：目录内独立编号（当前 01），不属于实现范围
```

## 归档约定

1. **编号目录内独立**：design/ 固定 01–06；rounds/ 每轮目录固定 `01-开发规划`、`02-集成验收记录`；guides/ 与 appendix/ 各自目录内从 01 顺序编号。不使用跨目录全局编号。
2. **每轮两份归档**：开工前在 `rounds/roundN/` 编写 01-开发规划（体例参照 round1/01：现状盘点 → 范围与验收基线 → 演进红线 → 里程碑 WBS → 验收用例 → 风险）；收官后归档 02-集成验收记录（体例参照 round1/02：实测证据 + 对账快照）。轮次归档为历史记录，除引用修正外不回改原文。
3. **设计基线原地修订**：后续轮次引入中间件等带来的口径变化，直接更新 design/ 对应文档并在当轮规划中记录变更，不另起副本。
4. **文档引用写法**：设计文档用「编号§章节」（如 02§八、03§六.3）；轮次文档用「RN规划§章节 / RN验收§章节」（如 R1规划§6.5、R1验收§四），RN 为轮次序号。代码注释与正文统一此写法。
5. **sql 脚本与文档对应**：schema/schema_ext/seed 头部注释标注对应文档路径，路径变更时同步更新。
